# Historical regression test reconciliation — 30 October 2026

## Decision and scope

**Decision: adapt all 11 failing portable tests for today's stable app, retire none yet.** Every failing file still checks a real user-facing behavior; deleting a whole test would discard useful protection. The originals in `archive/tests-v5.26-original/` are immutable historical evidence and must not be edited. Changes belong in the maintained portable tests under `tests/`, with old and new expectations reviewed explicitly. A failing historical snapshot is **not** evidence of a production bug until the scenario is reproduced against the current contract.

This audit compares the archived v5.26 expectations with the current stable app's 68 courses × 3 levels, 142 melodies, compact navigation and timing semantics, as documented in `tests/TEST-STATUS.md`, `scripts/test.py` and `src/app/runtime.js`. It is a **test contract review**, not a claim that all failures have already been fixed. Run each repaired portable file and finally `python scripts/test_snapshot.py`; add it to CI only once it passes cleanly.

## Disabled or excluded checks

`scripts/test.py` currently selects **13 passing portable stable regression files** from the 24 retained files. The other 11 are **excluded from the standard CI gate**, but not deleted: `scripts/test_snapshot.py` runs all 24 and intentionally exits nonzero on their known failures. The repository also runs v6 tests, data validation, PWA/install tests, BLE reconnection and Playwright navigation/behavioral flows. There are no findings in the current inventory supporting deletion of an entire portable regression file merely for ease of passing CI.

## Proposed completion criteria for a subsequent implementation

1. Repair portable tests (not archived originals), comparing each expected transition with `src/app/runtime.js` and the built `index.html`. For each changed expectation, record the current behavior and why it is correct.
2. Preserve negative assertions, simulated input scenarios, and meaningful interaction coverage. Do not turn failures into warnings or add skips simply to make the status green.
3. Run `python scripts/test_snapshot.py` to 24/24 passing; run `python scripts/test.py` and both Playwright suites. Update the test status file with independently verified results.
4. Replace the maintained test runner's hardcoded list of 13 with discovery of all 24 passing portable tests and require them in GitHub Actions. Keep the frozen original archive for historical comparison.
5. Only delete a portable test if a reviewer identifies the exact removed feature, confirms no current functionality depends on it and records which current test replaces any remaining protection. Never remove the historical originals.
